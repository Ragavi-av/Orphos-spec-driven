# Layer document template

Use these sections in this order. Omit a section only if it genuinely does not apply, and say why
in one line rather than leaving it empty.

````markdown
# <Layer name>

> Generated by the architecture-understanding skill from commit `<hash>` on <YYYY-MM-DD>.
> Evidence paths are repo-relative. Tags: [inferred] [not implemented] [unverified].

## 1. Purpose
Two to four sentences: what this layer is responsible for and what it is explicitly not.

## 2. Components
| Component | Module path | Compose service : port | Responsibility |
|---|---|---|---|

## 3. Component diagram
```mermaid
flowchart LR
  %% this layer's components, plus the neighbouring layers they talk to (styled differently)
```

## 4. APIs and interfaces
Per component: inbound REST endpoints (verb, path, purpose, auth), Kafka topics consumed,
MCP tools exposed, scheduled jobs. Cite the controller/listener class.

| Verb | Path / topic / tool | Handler | Auth | Purpose |
|---|---|---|---|---|

## 5. Dependencies
| From | To | Mechanism (HTTP/Kafka/JDBC/SDK) | Configured by (env/property) | Evidence |
|---|---|---|---|---|

## 6. Key flows
For each important flow inside or through this layer: a `sequenceDiagram` followed by numbered
steps, each step citing the class/method.

## 7. Data & state
Stores, types/tables/collections owned, read or written; caches; schema bootstrap.

## 8. Configuration
Env vars / properties that change behaviour (names only, never secret values).

## 9. Guardrails in this layer
Rules this layer enforces or depends on (links to guardrails.md rows).

## 10. Gaps & drift
Discrepancies with existing docs, `[not implemented]` items, swallowed errors, mock fallbacks,
risks — each with a path.
````

## Special files

- **architecture.md**: purpose of the system; layered `flowchart TB` of all layers; table
  `Layer | Modules | Responsibility | Doc`; deployment topology diagram (compose files → networks →
  services); cross-cutting concerns (security, tenancy, observability) in a paragraph each with
  links.
- **flows.md**: one `sequenceDiagram` per end-to-end flow spanning ≥ 2 layers, each with a numbered
  step list citing code. Start with a table of flows → layers touched.
- **guardrails.md**: tables per group from guardrails.md §B; finish with a "Top risks" list ranked
  by impact.
- **README.md**: reading order, file table, commit + date, how to regenerate
  (`/architecture-understanding`, `/architecture-understanding <layer>`, `/architecture-understanding verify`).
